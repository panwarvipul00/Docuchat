## 1. Project Overview

DocuChat is a multi-user web app where users upload documents (PDF, DOCX, TXT) and ask questions about them in a chat interface. Answers are generated by an LLM **only from the uploaded documents**, and every answer includes **citations** (document name + page number).

**Purpose:** a portfolio/resume project that demonstrates full-stack + AI engineering:
RAG (retrieval-augmented generation), vector search, background jobs, auth, multi-tenancy, testing, and deployment.

## 4. Data Models

**User** — custom user model (email login).

**Workspace** — `id, name, owner(FK User), created_at`

**WorkspaceMember** — `workspace(FK), user(FK), role (owner|member)`

**Document** — `id, workspace(FK), uploaded_by(FK User), title, file, file_type, status (uploaded|processing|ready|failed), error_message, page_count, created_at`

**Chunk** — `id, document(FK), content(text), page_number, chunk_index, token_count, embedding(VectorField 1536), search_vector(SearchVectorField)`
- Add an HNSW index on `embedding` (cosine ops) and a GIN index on `search_vector`.

**Conversation** — `id, workspace(FK), user(FK), title, created_at`

**Message** — `id, conversation(FK), role (user|assistant), content, citations(JSON), tokens_used, created_at`

**Rule:** every query must be filtered by the user's workspace. A user must never see another workspace's data.

## 6. RAG Pipeline

### Ingestion (Celery task `process_document`)
1. Set status `processing`.
2. Parse file into a list of `(page_number, text)`.
3. Clean text (normalize whitespace, remove repeated headers/footers if simple).
4. Chunk: ~600 tokens per chunk, ~100 token overlap, never split mid-sentence if avoidable. Keep page number.
5. Embed chunks **in batches** (e.g. 64 at a time).
6. Bulk-insert Chunk rows; populate `search_vector`.
7. Set status `ready` (or `failed` with `error_message`).

### Question answering (`POST /ask/`)
1. Embed the question.
2. Retrieve top 8 chunks by cosine distance, **restricted to the workspace**.
3. (Phase 5) Hybrid: merge with full-text search results using Reciprocal Rank Fusion; optionally re-rank.
4. Build prompt:
   - System: answer only from the provided context; if the answer is not in the context, say "I couldn't find this in your documents."; cite sources as `[1]`, `[2]`.
   - Context: numbered chunks with document title + page.
   - Last ~6 messages of conversation history.
5. Stream the LLM response to the client (Server-Sent Events).
6. Save user + assistant messages with citations `[{index, document_id, title, page}]`.

## 8. Coding Conventions

- Python: type hints, black formatting, ruff linting. Business logic lives in `services/`, not in views.
- TypeScript: strict mode, no `any`. API calls only through `lib/api.ts`.
- All secrets in `.env` (never commit). Keep `.env.example` updated.
- LLM and embedding providers are accessed only through `services/llm.py` and `services/embeddings.py` so they can be swapped.
- Write the RAG logic directly (no LangChain/LlamaIndex) so the retrieval logic is clear and explainable in interviews.
- Every endpoint enforces workspace permissions; add a test for each one.
